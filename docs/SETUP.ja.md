# セットアップ

これは [SETUP.md](SETUP.md) の日本語版です。内容が食い違っている場合は英語版を正とします。

この文書では、コードを動かす前にブラウザ上で手作業で済ませておく必要がある手順を扱います。ツールの実行方法と OAuth リフレッシュトークンの取得は別の文書で扱います。

Google Cloud コンソールのラベルは時期によって変わります。以下のメニュー名が画面と一致しない場合は、最も近いものを探してください。

## はじめる前に

インポート先となる Gmail アカウントを決めます。あとで認可するのはこのアカウントです。Google Cloud プロジェクトの所有者と同じアカウントである必要はありません。

まずは捨ててよい別の Gmail アカウントでテストすることを検討してください。テスト中にインポートしたメールはきれいに取り消せないので、別アカウントにしておけば本来の受信トレイを汚さずに済みます。

## 1. Google Cloud プロジェクトを作る

1. [Google Cloud コンソール](https://console.cloud.google.com/) を開き、任意の Google アカウントでログインします。
2. ページ上部のプロジェクト選択メニューを開き、**新しいプロジェクト**（New project）を選びます。
3. 好きな名前を付けて作成します。

請求先アカウントは不要です。Gmail API の通常利用は無料です。

## 2. Gmail API を有効にする

1. 作成したプロジェクトを選んだ状態で、**API とサービス**（APIs & Services）>**ライブラリ**（Library）を開きます。
2. **Gmail API** を検索して開き、**有効にする**（Enable）をクリックします。

## 3. OAuth 同意画面を設定する

OAuth の設定は **Google 認証プラットフォーム**（Google Auth Platform）にあります。古いバージョンのコンソールでは **OAuth 同意画面**（OAuth consent screen）と呼ばれています。

1. **Google 認証プラットフォーム**を開き、案内が出たら**開始**（Get started）をクリックします。
2. **ブランディング**（Branding）で次の項目を入力して保存します。
   - **アプリ名**（App name）と**ユーザーサポートメール**（User support email）。これらを見るのは自分だけです。
   - **アプリケーションのホームページ**（Application home page）。このリポジトリ（または自分のフォーク）の URL で足ります。たとえば `https://github.com/<user>/pop3-to-gmail-import` です。
   - **アプリケーションのプライバシーポリシーのリンク**（Application privacy policy link）。同じリポジトリの [PRIVACY.md](PRIVACY.md) を指すようにします。たとえば `https://github.com/<user>/pop3-to-gmail-import/blob/main/docs/PRIVACY.md` です。
   - **承認済みドメイン**（Authorized domains）。上の 2 つのリンクで使ったドメインを追加します。この例では `github.com` です。
   - **デベロッパーの連絡先情報**（Developer contact information）。自分のメールアドレスです。

   ホームページとプライバシーポリシーは、アプリが**テスト**（Testing）の間は省略できますが、これらがないとアプリを本番に公開できません（ステップ 5 を参照）。このアプリは確認審査を受けないので内容が審査されることはありませんが、実際に存在するページを指すようにしてください。
3. **対象**（Audience）でユーザーの種類に**外部**（External）を選びます。**内部**（Internal）は Google Workspace 組織でしか選べません。
4. **データアクセス**（Data Access）で**スコープを追加または削除**（Add or remove scopes）をクリックし、次のスコープを手で追加します。

   ```
   https://www.googleapis.com/auth/gmail.insert
   ```

   このスコープはメールボックスへのメッセージ追加を許可するもので、`users.messages.import` もこれで足ります。既存メールの読み取りや削除は許可されません。

## 4. OAuth クライアントを作る

1. **クライアント**（Clients）で**クライアントを作成**（Create client）をクリックします。
2. アプリケーションの種類に**デスクトップアプリ**（Desktop app）を選んで作成します。
3. クライアントの JSON ファイルをダウンロードします。

このファイルにはクライアントシークレットが含まれます。リポジトリの中や共有された場所には置かないでください。

## 5. アプリを本番に公開する

**対象**（Audience）で**アプリを公開**（Publish app）をクリックして確定します。

ボタンが押せない状態になっている場合は、ブランディングの設定が埋まっていません。ボタンにカーソルを合わせると、何が足りないかが表示されます。特に、ステップ 3 のホームページとプライバシーポリシーのリンクは、ブランディングのページ上で必須と示されていないにもかかわらず、本番公開には必須です。

これは認可する*前*に済ませてください。公開ステータスが**テスト**（Testing）のままだと、外部ユーザーのリフレッシュトークンは 7 日で失効し、ツールは毎週止まることになります。

公開しても、アプリが一般に見えるようになったり検索に出たりはしません。`gmail.insert` は機密または制限付きのスコープで、かつアプリは未確認なので、認可するときに Google は「確認されていないアプリ」の警告を表示します。Google は 100 ユーザー未満の個人利用であれば未確認アプリを許容しているため、確認審査やセキュリティ評価は必要ありません。

あとで認可するときは、**詳細**（Advanced）>**(アプリ名) に移動**（Go to (app name)）を選んで警告を通過します。

## 6. Gmail アカウント側の準備

この Gmail アカウントが現在、**設定** > **すべての設定を表示** > **アカウントとインポート** > **他のアカウントのメールを確認**（Settings > See all settings > Accounts and Import > Check mail from other accounts）で同じ POP3 メールボックスを取得している場合は、切り替えるときにその設定を削除します。1 つの POP3 メールボックスに取得側が 2 つあると、同じメッセージを奪い合います。

削除は一方通行の操作です。Gmail は新しい POP3 取得設定の追加をもう受け付けないので、元に戻せません。

## 7. POP3 の情報をそろえる

取得元のメールボックスについて、次の情報を集めます。

- ホスト名
- ポート番号。POP3 over TLS なら通常 995、平文の POP3 なら 110
- TLS が必須か、あるいは利用可能か
- ユーザー名とパスワード

サーバーにウェブメールがあるなら、POP3 で削除したメッセージが実際に消えるのか、ゴミ箱フォルダに移るだけなのかを確認してください。ゴミ箱に残る場合、メールボックスは結局いっぱいになります。

## リフレッシュトークンが使えなくなったら

これまで動いていたリフレッシュトークンが無効になるのは、次のような場合です。

- アプリが**テスト**（Testing）ステータスのままだった。上で触れた 7 日の失効
- [Google アカウントのアクセス権](https://myaccount.google.com/permissions) でアクセスを取り消した
- Google アカウントのパスワードを変更した。Gmail のスコープを持つトークンはパスワード変更時に取り消されます
- トークンを 6 か月使わなかった
- 同じクライアントとアカウントの組み合わせで 101 個目以降のリフレッシュトークンが発行され、古いものが無効になった

いずれの場合も、もう一度認可して新しいリフレッシュトークンを取得します。
