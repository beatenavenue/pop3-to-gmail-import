# 使い方

これは [USAGE.md](USAGE.md) の日本語版です。内容が食い違っている場合は英語版を正とします。

この文書では、[SETUP.ja.md](SETUP.ja.md) の準備を済ませた後のツールの実行方法、出力と state ファイルの意味、インポートできなかったメッセージの扱いを説明します。

## 初回の実行の前に

### セットアップを済ませる

[SETUP.ja.md](SETUP.ja.md) のすべてのステップを、ステップ 10 と 11 の動作確認まで済ませ、`.env` に動作する POP3 と Gmail の設定が入った状態にします。

`.env` に相対パスで書いた `GOOGLE_CLIENT_SECRET_FILE` と `STATE_FILE` は、リポジトリの直下を基準に解決されます。ツールをどのディレクトリから起動しても同じなので、スケジューラーはどこからでも起動できます。

### フィルタのルールを書く

どのメッセージを破棄するかを決めるルールは `mail_filter.py` に書きます。このファイルはリポジトリに含まれていないので、リポジトリの直下で例をコピーして作ります。

```
cp mail_filter.example.py mail_filter.py
```

このファイルがないと、ツールは `error: mail_filter.py not found` で止まります。コピーしたままでは何も破棄しないので、ルールを書くまではすべてのメッセージがインポートされます。ファイル内の `should_discard()` の docstring に、メッセージの件名、アドレス、添付ファイルの読み方が書いてあり、その後にコメントアウトされたルールの例があります。

`mail_filter.py` は `.gitignore` に入っています。実際のルールには実在のアドレスを書くことが多いためです。ツールを別のホストに移すときは、`.env` と一緒に `mail_filter.py` も手でコピーします。

ルールが破棄したメッセージは、どこにも保存されずに POP3 サーバーから削除され、取り戻せません。新しいルールは、大事なメールボックスで使う前に、自分で送ったメッセージを入れたテスト用のメールボックスで試してください。

ルールが例外を出した場合、そのメッセージはインポートも削除もされません。[エラー](#エラー) を参照してください。

### 初回の実行で起きることを知っておく

初回の実行では、いま POP3 サーバーにあるメッセージを、最大で `MAX_MESSAGES_PER_RUN` 件、既定では 200 件まで処理します。どのメッセージも、Gmail にインポートされるかルールで破棄され、その後サーバーから削除されます。それより多くのメッセージがある場合は、続く実行で順に片付きます。いまサーバーにあるメールの控えを残したい場合は、先に通常のメールクライアントでダウンロードしておいてください。

## ツールを実行する

リポジトリの直下で次を実行します。

```
python3 mail_import.py
```

1 回の実行は次の順に進みます。

1. Gmail のアクセストークンを更新します。
2. POP3 サーバーにログインし、メッセージを UIDL で一覧にします。
3. メッセージごとに、最大で `MAX_MESSAGES_PER_RUN` 件まで、取得してルールを評価します。その結果に応じて、削除するか、Gmail にインポートしてから削除します。state ファイルに記録済みのメッセージは [state ファイル](#state-ファイル) で説明するとおりに扱います。
4. `QUIT` でセッションを終えます。POP3 サーバーが実際にメッセージを削除するのはこの時点です。

POP3 セッションを最後まで終えると、実行の最後に件数を 1 行、標準出力に表示します。

```
imported=3 discarded=1 rejected=0 skipped=0 deferred=0
```

- `imported` は、`INBOX` と `UNREAD` のラベル付きで Gmail にインポートし、サーバーから削除したメッセージの数です。
- `discarded` は、ルールが破棄したメッセージの数です。インポートせずに削除しました。
- `rejected` は、この実行で Gmail に拒否されたメッセージの数です。サーバーに残ります。
- `skipped` は、以前の実行で Gmail に拒否されたメッセージの数です。サーバーに残り、再送はしません。
- `deferred` は、`MAX_MESSAGES_PER_RUN` 件を扱い終えたために、その実行が手を付けなかったメッセージの数です。サーバーに残り、次の実行が先に扱います。

その実行で何も失敗しなければ終了ステータス 0 で、そうでなければ 0 以外で終わります。以前の実行で拒否されてスキップしたメッセージは失敗に数えません。エラーは標準エラー出力に出ます。

出力はメッセージを UIDL だけで示し、件名や差出人は出さないので、ログに残しても差し支えありません。

### 1 回の実行が扱う量

`.env` の `MAX_MESSAGES_PER_RUN` は、1 回の実行が一覧から取るメッセージの数を決めます。既定は 200 件です。それを超えた分はサーバーに残り、`deferred` に数えられます。上限に達することは失敗ではないので、実行は終了ステータス 0 で終わります。

上限は一覧のすべてのエントリを数えます。以前の実行で拒否されたためにスキップするだけのメッセージも含みます。メッセージはサーバーが一覧する順、つまり届いた順に取られるので、常に古いものからになります。

つまりメールボックスは 1 回ではなく複数回の実行で空になります。`deferred` が出続ける場合は、実行間隔と上限の組み合わせでは届く量に追いついていません。実行の頻度を上げるか、値を大きくしてください。

### エラー

エラーの行はすべて `error:` で始まります。UIDL を含む行は、そのメッセージ 1 通に関するものです。

- `error: <UIDL> rejected by Gmail with HTTP 400`、または `HTTP 413`

  Gmail がメッセージそのものを拒否しました。413 はメッセージが大きすぎることを示します。メッセージはサーバーに残って拒否済みとして記録され、以降の実行ではスキップされます。0 以外で終わるのはこの実行だけなので、このエラーが報告されるのは 1 回です。[Gmail にメッセージを拒否されたとき](#gmail-にメッセージを拒否されたとき) を参照してください。

- `error: <UIDL> filter raised <exception> at mail_filter.py line <n>`

  ルールがこのメッセージで例外を出しました。メッセージはサーバーに残って記録はされず、ほかのメッセージは通常どおり処理されます。ルールを直すまで、毎回の実行が同じように失敗します。どのメッセージかは、[Gmail にメッセージを拒否されたとき](#gmail-にメッセージを拒否されたとき) で説明する `tools/show_info_from_uidl.py` で調べられます。

- `error: <UIDL> import failed, <reason>`

  Gmail に接続できなかったか、HTTP 401、403、429、5xx など、アカウントやサービスの側に理由がある拒否を受けました。実行はそこで止まります。それまでに処理したメッセージは削除され、残りは次の実行を待ちます。401 や 403 で失敗し続ける場合は [リフレッシュトークンが使えなくなったら](SETUP.ja.md#リフレッシュトークンが使えなくなったら) を参照してください。

- `error: token refresh returned <status> <response>`、または `error: token refresh failed, <reason>`

  アクセストークンを更新できず、何も取得していません。続く場合は [リフレッシュトークンが使えなくなったら](SETUP.ja.md#リフレッシュトークンが使えなくなったら) を参照してください。

- そのほかの `error:` の行

  POP3 の接続か、その設定で失敗しました。ログインの失敗などがこれにあたります。削除が有効になるのは `QUIT` の時点なので、この実行ではメッセージは 1 通も削除されません。この実行ですでにインポートしたメッセージは state ファイルに記録されており、次の実行でインポートし直さずに削除されます。

### 定期的に実行する

ツールは 1 回動いて終了します。メールボックスを空に保つには、cron などのスケジューラーから、都合のよい間隔で起動します。`.env`、`mail_filter.py`、state ファイルは `mail_import.py` と同じ場所から探すので、スケジューラーはどのディレクトリからでもフルパスで起動できます。

何らかの失敗通知と組み合わせてください。対応が必要なことを知らせる手がかりは、0 以外の終了ステータスだけです。`deferred` はその手がかりには含まれません。上限に達しても終了ステータスは 0 だからです。メールの多いメールボックスでは、件数の行も合わせて見てください。

POP3 のメールボックスは、同時に 1 つのセッションしか使えません。前回の実行が終わらないうちに次が始まった場合や、メールクライアントが同じメールボックスを確認している最中は、ログインに失敗して 0 以外で終わります。次の実行で再試行されます。

## state ファイル

ツールは、後の実行でそのメッセージに何が起きたかを分かるように、一部のメッセージを state ファイルに記録します。パスは `.env` の `STATE_FILE` で、既定は `state.txt` です。相対パスはリポジトリの直下を基準に解決されます。ファイルは初回の実行で作られ、`.gitignore` に入っています。

各行には状態と UIDL が書かれます。UIDL は POP3 サーバーが各メッセージに付ける識別子です。

```
imported 000001a2b3c4d5e6
rejected 000001a2b3c4d5e8
```

- `imported` は、Gmail にインポートしたことを示します。この行はサーバーからメッセージを削除する前に書き込まれます。その後、削除が有効になる前にセッションが失敗した場合、次の実行はサーバーに残っているメッセージを見つけ、2 回目のインポートはせずに削除します。
- `rejected` は、Gmail に拒否されたことを示します。メッセージはサーバーに残り、以降の実行ではスキップされて `skipped` に数えられます。

ルールで破棄したメッセージは記録しません。ルールをもう一度評価すれば同じ結果になるためです。

毎回の実行の最初に、サーバーにもう無いメッセージの行は取り除かれます。これはメールボックス全体を見るので、その実行が実際に扱うメッセージだけが対象ではありません。拒否されたメッセージをサーバーから削除すれば、次の実行でその行が取り除かれます。ファイルがサーバーにあるメッセージの分を超えて大きくなることはありません。

ファイルに入っているのは UIDL だけで、メッセージから取り出した情報は一切含みません。

ツールの実行中はファイルを編集しないでください。手で編集する必要があるのは、拒否されたメッセージを再試行するためにその `rejected` の行を消すときだけです。`imported` の行は消さないでください。メッセージが 2 回インポートされることがあります。

## Gmail にメッセージを拒否されたとき

拒否されたメッセージは、対処するまで POP3 サーバーに残り、容量を使います。ツールの出力は UIDL しか示さないので、次の手順でどのメッセージかを調べます。

### 1. UIDL を確かめる

`error: 000001a2b3c4d5e8 rejected by Gmail with HTTP 400` のようなエラーの行か、state ファイルの `rejected` の行から UIDL を取ります。

### 2. メッセージを調べる

リポジトリの直下で、UIDL を引数にして次を実行します。

```
python3 tools/show_info_from_uidl.py 000001a2b3c4d5e8
```

これは `.env` から POP3 の設定を読み、メッセージを取得して、どのメッセージかを見分けるのに必要な情報を表示します。

```
Subject:     Quarterly report
From:        Example Sender <sender@example.net>
To:          user@example.com
Cc:
Date:        Tue, 15 Sep 2026 10:11:00 +0000
Received:    Tue, 15 Sep 2026 10:11:12 +0000
Message-ID:  <20260915101100.12345@mail.example.net>
Attachments: 1
Size:        48,213 bytes
```

- `Date` は送信者が付ける日時で、特に迷惑メールでは正しくないことがあります。`Received` は一番上の `Received` ヘッダーの日時で、たいていは POP3 サーバーがメッセージを受け付けた時刻を示します。
- `Attachments` は、ファイル名を持つ MIME パートの数です。判定は `mail_filter.example.py` にあるルールの例と同じです。署名欄の画像のようなインライン画像も数に入ります。
- `Size` は、サーバーが保持しているメッセージ全体の大きさで、ツールが Gmail にアップロードする大きさでもあります。添付ファイルはメッセージの中でエンコードされているので、ファイルそのものより 3 割ほど大きくなります。

デコードできないヘッダーはメッセージに書かれたままの形で表示し、制御文字は `\x1b` のようにエスケープして表示します。

このツールはメッセージを削除せず、ディスクにも何も書きません。ただし出力には件名やアドレスが含まれるので、ログには送らないでください。インポートと同じく、ほかのセッションがメールボックスを使っている間はログインできないので、インポートが動いていないときに実行します。

メッセージがもうサーバーに無い場合は、`error: <UIDL> is not on the server` を表示して 0 以外の終了ステータスで終わります。

### 3. メールクライアントでメッセージを開く

上の出力は、メッセージを見つけるためのもので、読むためのものではありません。本文や添付ファイル、すべてのヘッダーを見るには、Thunderbird などの通常の POP3 クライアント、あるいはサーバーにウェブメールがあればそれでメールボックスを開き、件名、差出人、日時からメッセージを探します。

POP3 クライアントはツールと同じメールボックスを扱うので、接続する前にアカウントの設定を確認してください。

- メッセージをサーバーに残す設定にし、一定の日数が過ぎたら削除する設定も外します。そうしないと、ダウンロードしたメッセージがサーバーから削除され、Gmail に届かなくなります。
- 新着メールの自動確認を切ります。ツールの実行中にメールボックスを使ってしまわないようにするためです。

クライアントは、ツールがまだ処理していないメッセージもダウンロードします。サーバーに残してさえいれば、それらは次の実行で通常どおりインポートされます。

### 4. メッセージを片づける

どのメッセージか分かったら、必要なものを保存し、メールクライアントかウェブメールでサーバーから削除します。次の実行で state ファイルからその行が取り除かれます。

削除せずに、ツールにもう一度インポートを試させたい場合は、state ファイルからその `rejected` の行を消します。次の実行で Gmail に再送されます。
